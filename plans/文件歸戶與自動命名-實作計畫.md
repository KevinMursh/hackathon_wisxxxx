> 日期：2026-09-12　依據：`prototype-v4-確認清單.md`（歸戶確認站已移除、步驟一逐檔浮現「原檔名 → 類型・來源・一句摘要」、卷宗瀏覽器就地改標籤）

> 狀態：☑ 正規化（35 案綠）　☑ 分類（tune 20/20、case02 21/21、合併卷宗 17 段）　☐ API　☐ EC2　☐ S3/DynamoDB

## 0. 拍板前提

| 決定 | 內容 |
|---|---|
| 無確認閘門 | 分類結果直接回前端進工作畫面；人工修正走 `PATCH`，寫稽核，不擋流程 |
| 判定以內容為準 | 不看檔名；亂檔名 demo 真送後端跑 |
| 來源只在有證據時才判 | 文件本身有機關印信／抬頭／發文字號／簽名欄／訴願書格式才給來源；照片、影片、無抬頭截圖一律 `未知`。**`未知` 是正式值，不猜** |
| 沒有 fallback | 後端失敗回錯誤碼與訊息，不回假成功；前端如何呈現是 v5 的事 |
| 命名 = 分類產物套模板 | `suggestedName` 由 `doc_type/date/doc_no/source` 組成，不另做分析；`PATCH` 可人工改名（寫稽核）；`GET files` 同時回 `originalName` 與 `suggestedName`；**S3 key 不改**，同一次上傳兩個視圖 |
| 影片只判類型 | 3 幀＋時長足以得出 `採證影片、日期`；內容（幾秒發生什麼）留分析階段 |
| 合併卷宗自動分段 | 一份多頁 PDF 回多筆 segment，步驟一清單自然長出多列；確認拆檔留 v5 |

## 1. 架構：三段式

```
原始檔（pdf/odt/docx/jpg/heic/mp4/zip/txt…）
   │ ① 正規化 normalize.mjs（純工具，零 LLM）
   ▼
中間格式 {text, textPerPage, images[], meta}    ← 存 S3，下游擷取／對照／異議翻卷證共用
   │ ② 標籤 classify.mjs（多檔裝箱，每箱一次 Converse 呼叫；箱數通常 1–3）
   ▼
{results:[{fileId, segments:[{fromPage,toPage,doc_type,source,form,date,doc_no,summary,confidence,evidence}]}]}
   │ ③ 逐箱推給前端（SSE）；人工修正 PATCH → 稽核
```

不直接把原生檔丟 LLM 的理由：Bedrock Converse 對 Claude 的 `document` block 是先抽文字再給模型（掃描 PDF 抽出空白、看不到印信版式）；odt／mp4／heic／zip 不支援；下游需要 `textPerPage`、每頁圖、sha256、magic bytes 做定位／去重／拆檔，只有工具層會產。

## 2. ① 正規化 `server/normalize.mjs`

**輸出**

```js
{
  fileId, originalName, sha256, bytes, mime,
  kind: "pdf-text" | "pdf-scan" | "image" | "video" | "office" | "text" | "unsupported",
  pages, duration,
  text, textPerPage: [],
  images: [],                      // 頁圖路徑
  exif: { takenAt },
  warnings: []
}
```

**分派（magic bytes 先於副檔名，`file-type`）**

| 判定 | 工具 | 規則 |
|---|---|---|
| PDF | `pdftotext -layout`、`pdftoppm -r 110 -png` | 去空白後 < 50 字/頁 → `pdf-scan`，否則 `pdf-text` |
| docx | `mammoth` 抽文字；版式圖走 soffice→pdf | |
| doc / odt / rtf | `soffice --headless --convert-to pdf` | 轉完走 PDF 路徑；失敗 → `unsupported` |
| jpg / png / webp / heic | `sharp`（heic 需 libheif） | 長邊 1,600px 轉 PNG；讀 EXIF |
| mp4 / mov | `ffprobe` 時長；`ffmpeg` 抽首／中／尾 3 幀 | 不抽音軌 |
| zip | 解壓後遞迴 | 子檔各自一筆 |
| txt / md / csv | 直接讀 | |
| 其他 | 不動 | `unsupported`，不呼叫模型，回 `其他／無法辨識內容` |

**頁圖規則**

| kind | images |
|---|---|
| `pdf-text` | 第 1 頁＋最後 1 頁 |
| `pdf-scan` | 全部頁，每 20 頁一批（Converse 單則上限 20 張圖） |
| `image` | 1 |
| `video` | 3 幀 |

分析階段要看第 N 頁再 `pdftoppm -f N -l N` 補產。

**錯誤處理**：單檔工具失敗 → 該檔 `{ok:false, error:{code:"NORMALIZE_FAILED", message}}`，其餘檔繼續；不吞錯不假成功。抽出文字**不修**，「○」原樣保留。

**依賴（EC2 user-data）**：`poppler-utils`、`libreoffice-writer`、`ffmpeg`、`file`；Node：`sharp`、`file-type`、`mammoth`。

## 3. ② 標籤 `server/classify.mjs`

**呼叫**：`@aws-sdk/client-bedrock-runtime` Converse；`toolConfig` 強制 JSON schema；模型由 `MODEL` 環境變數切換（預設 `us.anthropic.claude-sonnet-4-5-20250929-v1:0`，備選 `us.anthropic.claude-opus-4-5-20251101-v1:0`），以 5.2 對照數據定案。

**批次裝箱（生產路徑）**：一次呼叫處理多檔，不是一檔一次。三個預算先到先開新箱：**≤ 10 檔**（防大量檔案互相干擾；數字由 5.2 掃 5／10／18 定案）、**≤ 20 張圖**（Converse 硬限制）、**≤ ~100k 輸入 token**。case02 18 檔 → 2 箱 2 次呼叫，約 40–60 秒。多頁掃描 PDF 可能獨占一箱。正規化失敗的檔不進箱。

**給模型（批次）**：content 陣列**交錯排列**——每檔一個 `=== FILE {fileId} | 原檔名 | kind ===` 文字標頭，該檔的圖／文字緊接其後，不把圖集中堆在最後；`pdf-text` → `[p1]…` 逐頁全文（截 8,000 字），**不送頁圖**；`pdf-scan` → 全頁圖；`image` → 1 圖＋EXIF；`video` → 3 幀＋時長；`text` → 文字。裝箱時**同類型打散**（連續多張相似照片／掃描件不相鄰）。

**跨檔張冠李戴防線**：輸出 `results[]` 每筆必帶 `fileId`，程式核對集合等於送入集合——多的丟、少的補 `{ok:false, error:"MISSING_IN_RESPONSE"}` 後單檔補跑；`evidence` 須引用該檔內可見字樣，若在該檔文字中找不到 → `confidence` 打折並標 `evidence_unverified`。文字與圖混合本身不是風險（Claude 原生多模態），風險只在歸屬錯檔。

**單檔模式（eval／debug）**：`--per-file` 一檔一次呼叫，文字 PDF 加送首尾頁圖；用來對照批次是否因跨檔干擾掉準度，不是生產路徑。

**輸出 schema**

```json
{
  "segments": [{
    "fromPage": 1, "toPage": 3,
    "doc_type": "裁處書送達證書",
    "source": "原處分機關",
    "form": "掃描",
    "date": "114-09-18",
    "doc_no": "新北環稽字第41-114-090351號",
    "party_hint": "鄭○芳",
    "summary": "郵務送達，本人簽收於 114-09-18",
    "confidence": 0.92,
    "evidence": "頁首「送達證書」字樣＋簽收章＋郵務送達勾選"
  }]
}
```

`summary` 對應 v4 步驟一「一句摘要」與卷宗列次行。單一文件 = 一筆 segment；合併卷宗 = 多筆。

**三軸推導欄位（不問模型）**：下游「主張 vs 卷證事實」分槽用的是 來源 × 性質 × 時點 三軸；來源由模型判，另外兩軸由程式推出——
- `nature`：由 doc_type 查表 → 主張（訴願書／答辯書／陳述意見書／申請書／檢舉）｜紀錄（裁處書／送達證書／稽查紀錄／簽呈／車籍／係數表／決定書）｜證物（照片／影片／影像放大／檢驗報告）
- `timing`：整案後處理，以該案「裁處書」date 為界 → 處分作成前｜處分作成｜爭訟發生後｜未知
27 類 doc_type 不能省：期間計算要「裁處書送達證書」（非通知書送達證書）、欄位擷取要「訴願書」、答辯書要拆檢送函，都比三軸細；且 41 檔驗證全對，模型判標題比判三軸容易。前端顯示可只用三軸分組。

**doc_type 封閉清單**：訴願書、訴願委任書、答辯書、答辯書檢送函、卷證目錄、裁處書、裁處書送達證書、陳述意見通知書、通知書送達證書、陳述意見書、檢舉資料、稽查紀錄、調查筆錄、採證照片、影像放大標註、採證影片、車籍資料、係數計算表、簽呈、檢驗報告、契約書、委員會決定書、其他

**source 判定規則（prompt 寫死）**

| source | 判定證據（缺一律 `未知`） |
|---|---|
| 訴願人 | 訴願書格式、訴願人署名、委任書、陳述意見書署名 |
| 原處分機關 | 機關抬頭／印信／發文字號／承辦章（裁處書、送達證書、稽查紀錄、簽呈、答辯書、通知書、車籍查詢） |
| 第三方 | 他機關抬頭／法院文書／檢舉平台系統畫面且非原處分機關 |
| 本局 | 訴願審議委員會決定書、審議紀錄 |
| 未知 | 照片、影片、無抬頭截圖、任何無法從內容確認身分者 |

**後處理（程式）**

- `doc_type=其他` → `summary` 固定「無法辨識內容」
- 重複：sha256 相同 →「重複」；`doc_type+date+doc_no` 三同 →「疑似重複」
- `suggestedName = {序}-{doc_type}_{date或文號尾碼}_{source}.{ext}`，序號依法定順序表；`source=未知` 時省略該段
- 結果以 sha256 為 key 寫 cache，同檔重跑 0 呼叫
- Bedrock 錯誤：節流 → 指數退避重試 3 次；仍失敗 → 該檔 `{ok:false, error:{code:"BEDROCK_THROTTLED"}}`；認證／模型不可用 → 整批 503

## 4. API `server/server.mjs`（Express + multer）

| Endpoint | 動作 |
|---|---|
| `POST /api/cases/:id/files` | 收整批（multipart）→ 存 S3 原檔 → 立即回 `{jobId, files:[{fileId, originalName}]}` → 背景序列跑 normalize+classify |
| `GET /api/jobs/:jobId/events` | **SSE**：每完成一箱推該箱所有 `{fileId, ok, segments | error}`；最後推 `done`。case02 為一波全出，v4 步驟一的逐檔浮現由前端排隊演 |
| `GET /api/jobs/:jobId` | 同資料，輪詢版 |
| `PATCH /api/cases/:id/files/:fileId` | 改 `doc_type/source/suggestedName`（支援 segment 索引）→ 寫稽核 `{欄位, 原判定 → 人工改為, by, at}`；改類型／來源後若未同時給名，`suggestedName` 依模板重算 |
| `GET /api/cases/:id/files` | 目前歸戶狀態（含人工修正後）；每筆同時回 `originalName`、`suggestedName`、`downloadUrl`（presigned，`Content-Disposition` 帶 suggestedName） |
| `GET /api/health` | 檢查 Bedrock 憑證與外部工具存在 |

**錯誤碼**：`UNSUPPORTED_FORMAT`、`NORMALIZE_FAILED`、`BEDROCK_THROTTLED`、`BEDROCK_UNAVAILABLE`、`SCHEMA_INVALID`（模型回非法 JSON）、`S3_WRITE_FAILED`。

**儲存**：原檔＋正規化產物 → S3 `cases/{id}/raw/`、`cases/{id}/normalized/`；判定、人工修正、稽核、cache → DynamoDB 單表（PK `CASE#{id}`；SK `FILE#`、`AUDIT#`、`CACHE#{sha256}`）。

### 5.3 API（`curl`）

`curl -F` 上傳 case02 亂檔名版 → `curl -N` 看 SSE 逐檔到 → `PATCH` 改一檔來源 → `GET files` 看到修正與稽核 → 上傳壞檔看到 `ok:false`。

## 7. 已知限制

- 掃描 PDF 超過 20 頁分批，段落跨批時頁界可能錯 1 頁
- 批次模式失去真逐檔串流；一箱內任一筆模型輸出漏掉需單檔補跑
- 影片只判類型與日期，不做內容分析
- 合併卷宗本輪只回 segment，不真拆檔
- 正規化產物含全文，S3 不公開；demo 資料皆為模擬件
