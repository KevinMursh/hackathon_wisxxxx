# 評測用資料集（Eval Set）— 勿用於 RAG／訓練／few-shot

日期：2026-09-12
方法：從 `資料集/命題方提供/歷史訴願決定書/` 挑 3 份**真實**決定書，依官方
`訴願書範例官方`／`答辯書範例官方` 模板格式，把決定書「事實／理由」段記載的
內容**反推重建**成訴願書＋答辯書全文；決定書本身（真實、未經改寫）當標準答案。

## 為什麼不能直接拿決定書當測資，也不能生成假案情

- 直接用決定書本身：決定書已經在 RAG 知識庫／few-shot 池裡，系統靠相似案例
  檢索就能直接「認出」同一份文件，分數會虛高，測不出真實能力
- 純生成假案情：案情、法條適用、爭點都可能不符合真實訴願書/答辯書的寫作邏輯
  與法律事實，AI 生成的「考題」本身就有幻覺風險

## 這批資料的做法

案情、法條適用、爭點、送達細節**全部真實**（來自決定書「事實」段對訴願意旨/
答辯意旨的摘錄）；只有「訴願書」「答辯書」這兩份輸入文件的**完整全文措辭**是
依官方模板重建的（因為原資料集從未收錄過完整的訴願書/答辯書全文，只有決定書
摘錄過的片段——見 `scenarios_kc/02-案件卷宗類型討論.md`）。

## ⚠️ 使用規則（跟 README.md 主文一致）

1. **這三份對應的原始決定書**（見下表）**必須從 RAG／向量庫／few-shot 語料庫中
   排除**，否則系統靠相似案例檢索直接抄答案，測不出真實能力
2. 知識庫建置（ingestion）腳本**不得掃到本資料夾**
3. 標準答案只能在**跑完系統輸出後**核對，不可先看答案再調整規則/prompt 去套用
   到這三案本身（可以看了之後回頭調整「一般性」規則，但不能為這三案量身訂做）
