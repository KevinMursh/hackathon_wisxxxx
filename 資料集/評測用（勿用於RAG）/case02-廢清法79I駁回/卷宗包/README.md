## 這是什麼、不是什麼

- **是**：依《訴願法》58 條 III（檢卷答辯）、75 條 I（據以處分之證據資料）、《行政程序法》102 條（陳述意見）
  與環保稽查實務，推導出「這個案子的卷宗**法律上必然存在**哪些文件」，再逐份製作。
  案情、文號、日期、法條、罰鍰、係數、訴辯主張全部取自真實決定書。
- **不是**：真實卷宗。每頁均有「黑客松測試用模擬文件」浮水印，印文標示「（模擬）」，個資全數遮蔽或虛構。
- 決定書本身（標準答案）**不在**本包內，且**須自 RAG／向量庫排除**（見上層 README）。

## 刻意留下的測試點

1. **收受日不一致**：訴願書自述「收受處分日 9/16」（訴願人常誤寫發文日），送達證書實際簽收日 **9/18**。
   系統應以送達證書為準計算 30 日期間（起算 9/19，屆滿 10/18；9/22 提起 → 未逾期）。
2. **三方主張衝突**：訴願書＋陳述意見書說「已拿回車上」；答辯書＋稽查紀錄＋影片 19 秒幀說「煙蒂留置水溝蓋」。
   系統應標紅並指向證據（05-03、06、13）。
3. **答辯書引用法條可查核**：廢清法 27①、50③、裁罰準則 2①①、環保署 108 年函——全部在 `命題方提供/相關法規` 與決定書內，可驗證為現行有效。
4. **形式混雜**：6 份文字 PDF、5 份掃描 JPG（含 2 份手寫）、2 份系統截圖、3 幀照片、1 段影片。
   文件歸戶功能若只在乾淨 PDF 上測，測不出東西。
5. **個資遮蔽方式與真實決定書一致**（○ 遮字、車號 000-0000、地址○○區），OCR 後不應把「○」當成錯字修正。

## 產製方式（可重跑）

- 腳本：`_build/build_docs.py`、`_build/build_media.py`（原始生成照片在 `_build/photos/`；腳本內 SP 路徑指向自身目錄，輸出到 ROOT）（HTML → Chrome headless PDF → pdftoppm → PIL 掃描效果；照片 nanobanana 生成後加行車紀錄器疊層；影片 PIL 逐幀 → ffmpeg libx264）

- 隨機種子固定（1141061379），重跑結果一致
